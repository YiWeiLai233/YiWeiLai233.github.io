未来观测站第一版选择静态维护，不做登录后台。原因很现实：个人站最重要的是内容能持续维护，而不是一开始就做复杂的后台系统。

## 内容集合

站点把内容分成两个核心集合：

- `projects`：项目档案，记录项目定位、技术栈、状态、仓库链接和长期复盘。
- `posts`：开发日志，记录某一次技术选择、问题排查、功能实现或阶段总结。

项目档案负责“这个项目是什么”，开发日志负责“这个项目是怎么一步步做出来的”。

## 为什么补项目详情页

早期项目页只显示卡片摘要，Markdown 正文虽然存在，但没有被页面渲染。这样维护档案时会很别扭：写了很多内容，用户却只能看到一句简介。

现在项目卡片可以跳到独立详情页，每个项目的 Markdown 正文都能被完整展示。这样后续只要在 `src/content/projects` 里改正文，就能更新对应档案。

## 静态维护的好处

静态站没有后台登录，也就少了账号、权限、数据库、接口和部署维护压力。内容变更通过 Markdown 和 Git 管理，更适合个人长期维护。

如果以后文章数量变多，可以再加搜索、标签筛选、项目归属和归档页。现在先保持简单，重点是把真实项目内容写扎实。

## 复盘

个人博客最容易变成漂亮空壳。未来观测站要避免这一点，就必须让内容结构服务于真实记录：项目是档案，日志是过程，收藏是兴趣，看板娘和视觉风格负责把这些内容串成一个有个人气质的网站。
