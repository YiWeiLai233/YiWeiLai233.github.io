题库原本是一个 88 KB 的 Markdown 文件，230 道题按章节排好，每道题后面跟着答案。直接丢进站点当一篇文章也能看，但"看"和"刷"是两回事——刷题要的是随机抽一题、想一下、点开对答案，然后下一题。所以这次把它做成了交互模块。

## 随机出题没用 Math.random()

第一版很直接：每次点"下一题"，从题库里 `Math.random()` 抽一个 id。写到一半意识到不对——230 题里刷 20 题，按生日问题算，期望撞题 1 到 2 次。刷题场景里重复出一道刚做过的题，体验比想象中糟得多。

改成洗牌队列：把**筛选范围内**的题打乱成一个队列，游标逐题往后走，走完一整轮再重洗。这样一轮之内绝对不会重复，而且"洗完一轮再来"的节奏本身也符合刷题习惯——先过一遍，第二遍再巩固。

顺带一个反直觉的点：筛选条件一变（比如切到只看 K8s），队列要重建，游标归零。不能保留游标，否则换了章节之后位置对不上，会跳到队列中间去。

## 题库为什么不进 HTML

题库 JSON 有 165 KB。如果首页把整份塞进 HTML，首屏体积会直接翻倍，而且首页那几张题卡根本用不上那么多数据。

所以拆成两份：

- 页面在**构建期**读题库，只渲染静态部分——总题数、章节分布、考前速记、复习路线。这些内容本来就该被搜索引擎和直接访问看到。
- **题目本体**由 island 在浏览器里 `fetch('/data/interview-bank.json')` 拿，筛选和出题全在客户端做。

代价是刷题区会先显示一句"题库加载中"，但换来的是首页 HTML 不背那 165 KB。

## 两个入口，不同密度

首页那块只要"随手刷两题"的轻体验，所以是紧凑模式：一张题卡、看答案、下一题，加一个"去刷题页"的按钮。筛选条塞进首页会显得很重，而且首页已经有项目、收藏、日志三块内容了。

独立的 `/interview/` 才是完整版：难度和章节筛选、进度计数、侧栏放题库概况和速记折叠区。速记那几节（必背端口、必记数字、一句话答案）其实更适合考前十分钟扫一眼，独立页有空间放，首页没有。

首页那块用 `client:visible` 懒水合——首屏没滚到就不加载 Vue 运行时，别为了一个可能没人点的区块拖慢首屏。

## 备份状态存什么、不存什么

筛选项和"已刷多少题"存 localStorage，跨会话有意义。

**出题位置不存**。因为每次进页面队列都会重洗，硬把上次的游标套回去只会错位——上次刷到第 17 题，这次队列已经重排过了，第 17 位是另一道题。想清楚这一点之后省掉了一整套"恢复进度"的逻辑。

## 一点收尾

题库源文件放在 `src/data/interview/` 下，唯一的真相是那个 Markdown。`scripts/build-interview-bank.mjs` 在 dev 和 build 前跑一遍，解析成 JSON。想加题就改 Markdown，脚本负责重新切分题干和答案——不用手工维护两份。

改动都在同一个 commit 序列里：题库模块、island 组件、独立页、首页区块、导航入口，各自独立提交。
