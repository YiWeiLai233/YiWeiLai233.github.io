感触科技官网 <https://hapticsys.com> 是我从零手写的企业站，没有用模板，也没有构建框架。页面结构、视觉样式、域名解析、证书、备案、服务器部署，一整条链路自己走完。这篇记录过程中真正花时间的部分。

## 先确定站点要说清什么

企业官网最容易犯的错是"什么都想说"。这家公司做的是具身触觉智能与边缘协处理芯片，客户是机器人厂商、传感器厂商和科研机构，他们打开网站只想确认三件事：你们做什么、技术到什么程度、怎么找你。

所以页面结构被压到四页：首页、关于我们、技术与产品、合作联系，加一个首页内的应用场景锚点。没有博客、没有招聘、没有新闻中心——这些栏目在没有持续内容供给的情况下，只会变成一堆挂着"敬请期待"的空页面，反而透露出一家公司的松散。

这个判断后来一直成立：整站八个页面（中英各四页）全部有实际内容，没有一页是为了"看起来完整"而存在的。

## 视觉：为什么不用科技蓝

方案里最纠结的是主色。芯片和机器人行业的默认配色是科技蓝加暗色背景，安全但雷同。

最后选了深绿（`#01594D`）作主色，配一个荧光绿（`#9EFF8C`）做强调。理由是这个产品讲的是**接触、压力、形变**——是机械臂碰到物体时的那一下，而不是数据在管道里流动。深绿更接近"材料"和"生理信号"的联想，比蓝色更贴题。配色定了之后，版式和动效才有依据：节奏上偏克制，动效只用来引导视线，不用来炫技。

实现上 Bootstrap 5.3.3 负责栅格和基础组件，`custom.css` 约 6400 行做视觉定制。所有颜色、字体、圆角、分割线都走 CSS 变量，改一处就能全站换肤——这一点在对接过程中救过命，客户提过两轮配色微调，都是改几个变量的事。

字体上刻意**不加载 Web Font**，全部走系统字体栈：`PingFang SC` / `Microsoft YaHei` / `Noto Sans SC` 依次回落。中文字体文件动辄几 MB，为了统一字形让首屏多等一两秒不划算。

## 备案：不能跳的一步

站点用的是国内服务器，所以 ICP 备案是硬前提。流程本身不复杂——主体信息、法人证件、网站负责人核验、服务器接入商审核，然后等管局审批。真正需要注意的是：

- 备案期间域名**不能对外提供访问**，先挂一个简单的占位页或者干脆不开端口；
- 备案号必须展示在页面底部并链接到工信部查询页，这是硬性要求；
- 后面如果加子域名或者换服务器，还要做变更备案，不是一劳永逸。

域名解析放在阿里云，和备案在同一个体系里，省去了跨平台核验的麻烦。

## HTTPS：证书自动续期比申请更重要

证书用 Let's Encrypt，签发本身是几条命令的事。真正需要设计的是**续期**：90 天有效期的证书如果靠人工记，迟早会漏。做法是配一个定时任务跑续期脚本，续期成功后自动 reload Nginx。

另外配了 HTTP 到 HTTPS 的 301 跳转，用户输 `hapticsys.com` 也会走到加密连接。这一步除了安全，还有一个实际好处：避免同一内容存在 http 和 https 两套 URL，那会让搜索引擎的权重分散。

## 部署：静态站也要认真对待服务器配置

站点是纯静态文件，Nginx 直接托管目录，开启 gzip，配置缓存头。部署就是上传文件，没有构建产物、没有 Node 进程、没有重启服务。

这套形态的维护成本极低——半年后回来改一个文案，只需要编辑 HTML 上传，不用回忆任何工具链。这是刻意的选择：企业官网的更新频率低，引入框架的收益撑不起它带来的记忆负担。

## 上线后才暴露的问题

本地预览一切正常，绑上真实域名之后问题才开始出现。下面几个都是这个阶段发现的。

**图片是最重的资产。** 首页首屏引用了八张图，合计约 1.5 MB，其中两张产品概念图分别是 550 KB 和 477 KB。静态站没有服务端渲染开销，首屏时间几乎就等于图片下载时间——所以图片压缩的收益远大于任何 JS 优化。后续应该转成 WebP 或 AVIF，目标压到 400 KB 以内。

**不存在的路径返回了 200。** 服务器上放了 `404.html`，但 Nginx 没有把它接进 fallback，结果任意乱输的地址都会返回 200 和首页内容。搜索引擎会把这类响应当成大量重复页面，用户也拿不到"这个页面不存在"的信号。本地预览看不出来，必须拿真实域名去请求一个不存在的地址才会暴露。

**WWW 和顶级域都能打开。** `http://hapticsys.com` 跳到 `https://www.hapticsys.com`，而页面 canonical 指向 `https://hapticsys.com`，两个地址都返回 200。规范做法是选一个主域，另一个 301 收过去，否则同一份内容有两套 URL 在索引里互相竞争。

**双语站的 hreflang 没成对。** 中文页没有声明英文版本，英文页只声明了自己。语言版本存在但 hreflang 不完整，等于告诉搜索引擎这两套页面可能没关系，英文站的收录会被拖慢。

**页面里还留着占位符。** 首页有两处「待填写：数据口径说明」和「待补充」。技术上线和内容上线是两件不同的事，前者靠流程保证，后者只能靠上线前对着页面逐屏读一遍。

## 复盘

做静态站的技术难度不高，难的是把"上线"当成一个完整状态来对待。域名、证书、备案、跳转、错误页、语言标注、占位内容——这些东西单拎出来都不复杂，但它们共同构成了"这个网站是正规的"这件事。

另一条经验是：**能用真实环境验的，不要用本地环境验。** 上面五个问题里有四个在本地预览时完全看不出来，全部是绑定真实域名之后才现形的。

顺带一提，验收这类小站点其实可以脚本化：扫描所有页面里的资源引用查断链、请求一个不存在的路径看状态码、检查每个页面是否有 canonical 和 hreflang、统计首屏图片总体积。写一次脚本，之后每次改动都能重跑。
