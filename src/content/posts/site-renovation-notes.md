未来观测站之前一直停在“写了一半”的状态：页面能跑，但缺分享卡片、缺标签页、缺部署流水线，图片还都是几 MB 的 PNG。这一轮把它推到正式上线，顺手把阅读体验和站内导航补齐。下面按决策顺序记录。

## 先定部署形态

仓库原来叫 `anime-developer-blog`，最初打算用项目页部署在 `/<仓库名>/` 子路径下。子路径部署的代价比想象中大：所有站内链接、静态资源路径、RSS 和 sitemap 里的绝对地址都要带上前缀，`astro.config.mjs` 里的 `base` 和 `site` 得配合着写，一旦漏改某处就是一个 404。

最后选了更省事的方案：仓库改名为 `YiWeiLai233.github.io`，变成 GitHub Pages 用户站，直接部署在根路径 `https://yiweilai233.github.io`。这样 `base` 可以完全不设，`site` 就是最终地址，站内绝对路径全都自然成立。

## 图片先从 PNG 换到 WebP

装修前 `public/assets` 里堆着一批 0.6–2 MB 的看板娘 PNG，首页一张主视觉就能吃掉大半首屏带宽。这批素材全部转成 WebP 后整体体积降到原来的 6% 左右，视觉上几乎看不出差别。

这个改动看起来最不起眼，但对静态站的体验提升最直接：静态站没有服务端渲染开销，首屏时间基本就等于图片下载时间。

## SEO 不是加个 title 就完事

原来的 `BaseLayout` 只有 charset、viewport、description、title 四项。补齐的时候按“一个页面被分享出去需要哪些信息”来反推：

- canonical，避免带不带斜杠的地址被当成两个页面；
- Open Graph 与 Twitter card，决定分享到社交平台时那张卡片的标题、描述和配图；
- favicon，用观测镜造型画了一个 SVG，比 PNG 小且任意缩放不糊；
- `robots.txt` 排掉构建产物目录，同时声明 sitemap 位置；
- RSS 与 sitemap，前者给订阅者，后者给搜索引擎。

配图这一项要注意：`og:image` 必须是绝对地址，且尺寸不能太小，否则各平台会自己裁切或干脆不显示。

## 文章页补上阅读体验

单篇文章原来只有正文，读长文时没有任何定位手段。这一轮加了三样东西：

- **目录**：从 Markdown 正文里解析二三级标题生成，难点不是提取而是锚点对齐。Astro 渲染时给标题生成的 id 经过 slugger 处理，中文标题会变成拼音之外的形式，自己拼一套规则必然对不上，所以生成目录时也用同一套 slugger 逻辑，跳过代码围栏避免把注释里的 `#` 当成标题。
- **阅读时长**：中文按每分钟 350 字估算，英文按每分钟 200 词，取整后显示在标题下方。数字不必精确，作用是给读者一个心理预期。
- **上下篇导航**：按发布日期倒序计算前后篇，文末给出“更早一篇 / 更新一篇”，读完了能顺着读下去。

另外给文章页输出了 `BlogPosting` 结构化数据，把作者、发布日期、标签、分类、阅读时长写进去。搜索引擎拿到这些字段后，展示的是有作者和日期的结果，而不是一段干巴巴的链接。

## 标签从装饰变成入口

日志卡片上的标签原来只是一排不可点的文字。这一轮的改法是：把标签变成链接，新增 `/tags/` 索引页列出全部标签和各自篇数，再给每个标签生成一个详情页，页面内提供相邻标签方便横向跳转。

中文标签要记得编码。`/tags/未来观测站/` 这种路径在构建里能过，但线上会变成一串百分号编码，所以生成链接时统一走 `encodeURIComponent`，实际测下来这种地址返回 200 正常。

## 部署交给 Actions

加了 `.github/workflows/deploy.yml`：推送到 `main` 就构建并发布到 Pages，不再需要本地构建后手动上传。这一步的意义是把“忘记发布”这类失误从流程里去掉——改完推上去就该是线上的样子。

## 收尾与验收

上线前做了几轮检查，都是能自动化的部分：

- 扫描构建产物里所有 `href` 和 `src`，确认没有指向不存在文件的链接；
- 检查所有图片都有 `alt`，缺 alt 的图片对屏幕阅读器和搜索引擎都不友好；
- 用浏览器在 390 / 768 / 1440 三档宽度下逐页检查有没有横向溢出；
- 检查正文与背景的对比度；
- 键盘 Tab 走一遍，确认焦点环清晰可见；
- 确认系统开启“减少动态效果”时动画会降级。

上线后再把关键路径点一遍：首页、日志列表、文章详情、标签页、项目档案、RSS、sitemap、`robots.txt`、favicon、404 页全部返回预期状态。

## 复盘

这一轮没有写复杂功能，做的都是静态站该有的基础件。真正有价值的两点是：**先定 URL 形态再动手**，子路径和根路径会渗透到每一处链接；以及**把检查脚本化**，断链、缺 alt、横向溢出这类问题靠肉眼在几十个页面上是看不过来的。

后续想继续做的方向是给日志加项目归属筛选，以及内容再多一些之后做归档页——现在日志只按时间平铺，篇数上来之后不好翻。
