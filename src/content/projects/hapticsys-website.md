感触科技官网（<https://hapticsys.com>）是我从零手写的企业站点，服务于一家做具身触觉智能与边缘协处理芯片的公司。从页面结构、视觉样式到域名解析、HTTPS 证书、ICP 备案和服务器部署，整条链路都是自己走完的。

站点不是模板套壳：视觉语言、版式栅格、动效节奏都是按这家公司"触觉"这件事重新设计的，底色用深绿而非科技蓝，是因为产品讲的是接触与压力，而不是数据流。

## 项目定位

企业官网的目标很具体——让来访的机器人厂商、传感器厂商和科研机构在三屏之内弄清楚"你们做什么、技术到什么程度、怎么找你们"。

这决定了页面结构只能是四页加场景锚点：首页讲清定位与技术指标，关于页交代孵化背景与团队，技术与产品页展开"感-算-控"三合一架构与工具链，合作联系页收口到邮箱与电话。没有博客、没有招聘、没有多余的栏目——那些是后续内容量真正上来之后才值得加的东西。

## 核心能力

- 中英双语：中文站四页，`/en/` 下另有一套英文页面，供海外对接与会议材料引用。
- 首页承载核心叙事：从"让机器人真正感知世界"到"触觉小脑"，再到技术闭环、技术指标、应用场景、合作生态。
- 技术指标区：把能效（pJ/SOP）、闭环延迟、异构信号路数、工具链效率提升等硬指标做成可扫读的卡片，而不是塞进段落。
- 动效：滚动入场、数字滚动、视差、分屏文字等基于 GSAP 与 IntersectionObserver 的实现，降级时不影响阅读。
- SEO 基础件：`robots.txt`、`sitemap.xml`（八条 URL）、`site.webmanifest`、多尺寸 favicon、Open Graph 与 Twitter card、canonical。
- 部署与证书：Nginx 托管静态文件，HTTP 到 HTTPS 强制跳转，证书由 Let's Encrypt 签发并自动续期。

## 技术结构

站点是纯静态的：HTML + CSS + 少量 JavaScript，没有构建步骤，改一行 CSS 保存即生效。这套选择的理由是维护成本——公司官网内容更新频率低，引入框架只会让半年后的自己多记一套工具链。

样式上用了 Bootstrap 5.3.3 作为栅格与基础组件，再叠一层自写的 `custom.css`（约 6400 行）做视觉定制。设计令牌全部走 CSS 变量：主色 `#01594D`、强调色 `#9EFF8C`、分割线用带透明度的同色系（`#3B545024`），字体栈优先系统中文字体，不加载 Web Font 以避免首屏被字体文件拖住。

交互层是 jQuery 3.7.1 加一组插件：Swiper 负责轮播，GSAP + ScrollTrigger 负责滚动叙事，WOW.js 负责入场动画，Magnific Popup 负责图片放大，Isotope 负责筛选布局。这些库的共性是有现成的手感和稳定的边界行为，比自己重写动画队列更划算。

部署侧是 Nginx 直接托管静态目录，开启 gzip，HTTP 请求 301 到 HTTPS。域名在阿里云解析，证书到期后自动续期，不需要人工介入。

## 值得复盘的地方

**一是图片是最容易漏掉的性能项。** 首页首屏引用了八张图，转成 WebP 之前合计约 1.5 MB，其中两张产品概念图各占 550 KB 和 477 KB。静态站没有服务端渲染开销，首屏时间几乎就等于图片下载时间，所以图片压缩的收益远大于任何 JS 优化。

**二是"静态站"也要处理错误路径。** 服务器上放了 `404.html`，但 Nginx 的 `try_files` 没有把它接进 fallback，结果任意不存在的路径都会返回 200 和首页内容——搜索引擎会把它当成一堆重复页面收录，用户也拿不到"页面不存在"的信号。这类问题在本地预览时完全看不出来，必须拿真实域名去请求一个不存在的地址才会暴露。

**三是 WWW 与顶级域必须收口。** 现在 `http://hapticsys.com` 会跳到 `https://www.hapticsys.com`，而 canonical 指向的是 `https://hapticsys.com`，两个地址都能返回 200。规范做法是统一到一个主域，另一个用 301 收过去，否则同一份内容会有两套 URL 在索引里竞争。

**四是双语站点的 hreflang 要成对写。** 语言版本存在而 hreflang 不完整，等于告诉搜索引擎"这两套页面可能无关"，英文站的收录会被拖慢。

**五是页面里最扎眼的问题往往是占位符。** 上线后仍有「待填写：数据口径说明」和「待补充」这样的标记留在页面上。技术上线和内容上线是两件事，前者靠流程保证，后者只能靠上线前对着页面逐屏读一遍。

## 后续维护方向

- 首页图片转 WebP 或 AVIF，目标把首屏图片总量压到 400 KB 以内。
- 接上真正的 404 处理，并把 WWW 与顶级域统一到单一主域。
- 补齐中英双向 hreflang，让两个语言版本互指。
- 清理页面上的占位内容，把技术指标的统计口径写清楚。
- 合并与延迟加载前端库：目前 17 个脚本里有几个只在特定区块用到，可以按需加载。
- 内容量真正增长后，再考虑拆出新闻或资料下载栏目。
