未来观测站是我的个人静态站，也是这些项目档案和开发日志最终展示的地方。它的定位不是传统简历页，而是一个带二次元视觉风格的长期记录空间：项目放进档案，开发过程写成日志，兴趣内容放进观测收藏。

站点已正式上线，地址是 <https://yiweilai233.github.io>，仓库公开在 [YiWeiLai233.github.io](https://github.com/YiWeiLai233/YiWeiLai233.github.io)。

## 项目定位

选择静态站，是为了把维护成本压低。没有登录后台，也不需要数据库；内容通过 Markdown 文件维护，写完后构建成纯静态页面发布。这样后续要改项目、加文章、换图片，都可以直接在仓库里完成。

部署形态上选的是 GitHub Pages 用户站，而非项目页子路径。原因是子路径会让所有站内链接、静态资源、RSS 和 sitemap 里的绝对地址都带上前缀，配置里要同时维护 `base` 和 `site`，漏改一处就是 404。改成用户站后博客落在根路径，地址干净，配置也只剩一个 `site`。

## 核心能力

- 首页：展示看板娘主视觉、项目入口、开发日志和二次元收藏。
- 项目档案：整理已有项目的定位、功能、技术栈、复盘和维护方向。
- 开发日志：按时间记录实现思路、问题排查和阶段性复盘，带阅读时长与上下篇导航。
- 文章目录：从 Markdown 正文解析二三级标题生成悬浮目录，锚点与渲染结果保持一致。
- 标签体系：标签可点，有索引页和逐标签详情页，支持相邻标签横向跳转。
- 观测收藏：保留番剧、游戏、音乐、碎片灵感等偏兴趣向内容。
- 订阅与检索：提供 RSS 与 sitemap，配合 robots.txt 交给搜索引擎。
- 分享与识别：补齐 canonical、Open Graph、Twitter card、favicon 和文章的结构化数据。
- 看板娘与 Q 版点缀：主图负责氛围，Q 版角色只做背景和边角装饰。
- 响应式布局：桌面端保留侧栏信息，移动端改成单列阅读。

## 技术结构

站点使用 Astro 内容集合管理 Markdown，页面由 Astro 组件组成，少量交互由 Vue island 承担。项目和日志都放在 `src/content`，修改内容时不需要改数据库或后台接口。

阅读相关的逻辑抽在 `src/lib` 里：内容排序与日期格式化在 `content.ts`，目录提取在 `toc.ts`，绝对地址拼接在 `url.ts`。样式使用 Tailwind 加一层 CSS 变量作为设计令牌，深浅色调、圆角、阴影都从令牌取值。

部署走 GitHub Actions：推送到 `main` 后自动构建并发布到 Pages，不需要本地构建再手动上传。

## 值得复盘的地方

一是先把 URL 形态定下来再动手。子路径和根路径的差别会渗透到每一处链接、每一份 feed，后期再改成本很高。

二是性能主要卡在图片。原有的看板娘素材是 0.6–2 MB 的 PNG，转成 WebP 后整体体积降到原来的百分之几，视觉几乎无差；静态站没有服务端渲染开销，首屏时间基本就等于图片下载时间。

三是质量检查要脚本化。断链、缺 `alt`、横向溢出这类问题在几十个页面上靠肉眼看不出来，写成脚本扫一遍几秒钟就有结论。

## 后续维护方向

- 持续补齐真实项目档案，让项目页不再像临时展示。
- 为开发日志增加项目归属与按项目筛选，并考虑归档页。
- 继续优化看板娘、Q 版角色和页面背景的关系，保证角色装饰不遮挡正文。
- 内容量变大后再考虑站内搜索。
