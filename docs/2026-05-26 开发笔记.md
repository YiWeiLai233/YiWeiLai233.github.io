## 四、头像迁移到 MinIO

### 问题

之前头像用 base64 存 localStorage，换浏览器就丢了。

### 方案

头像上传到 MinIO，数据库存 objectName（对象路径），登录/查询时动态生成预签名 URL。

### 改动

**后端：**

| 文件 | 改动 |
|------|------|
| `DTO/User.java` | 新增 `avatarUrl` 字段 |
| `DTO/LoginResponse.java` | 新增 `avatarUrl`，登录时返回 |
| `loginMapper.xml` | SELECT 加 `avatar_url`，新增 `updateAvatarUrl` SQL |
| `LoginMapper.java` | 新增 `updateAvatarUrl` 方法 |
| `LoginService.java` | 登录时调用 `enrichAvatarUrl()` 生成预签名 URL |
| `UserController.java` | 新增 `POST /api/user/avatar`，查询用户时返回头像 URL |

**前端：**

| 文件 | 改动 |
|------|------|
| `api/user.ts` | 新增 `updateAvatarUrl()`，UserInfo 加 `avatarUrl` |
| `views/ProfileView.vue` | 头像上传改为：上传 MinIO → 保存 URL 到数据库 → 更新 store |
| `views/LoginView.vue` | 登录后存储 `avatarUrl` |
| `views/RegisterView.vue` | 注册后存储 `avatarUrl` |

### 关键设计

- 数据库存的是 MinIO 对象路径（如 `dreams/xxx.png`），不是完整 URL
- 预签名 URL 有效期 7 天，每次登录/查询时重新生成
- 头像在 `LoginResponse` 中返回，前端存 localStorage 作为缓存
- 梦境图片同理，查询时动态生成预签名 URL

### 部署注意

- 数据库需加列：`ALTER TABLE user ADD COLUMN avatar_url VARCHAR(500) DEFAULT NULL;`
- MinIO 需要已部署（图片上传功能的前置条件）

### 数据库 URL 清理（重要）

**问题**：早期版本的代码把 MinIO 预签名 URL（带 `?X-Amz-...` 签名参数的完整 URL）直接存进了数据库。预签名 URL 有效期只有 7 天，过期后图片就访问不了了。

**正确的做法**：数据库只存 objectName（如 `dreams/xxx.png`），每次读取时动态生成预签名 URL。这样 URL 永远不会过期。

**为什么要动态生成而不是存 URL**：
- 预签名 URL 有 7 天有效期，存进数据库 = 图片 7 天后失效
- objectName 是永久不变的路径，跟有效期无关
- 每次请求时生成新 URL，对用户来说无感（自动刷新）
- 头像和梦境图片都用这个策略，统一管理

**清理 SQL**：

```sql
-- 把旧的完整 URL 提取成纯 objectName
-- 例：http://192.168.199.136:9000/dream-archive/dreams/xxx.png?X-Amz-...
-- → dreams/xxx.png

UPDATE dream_content
SET image_url = SUBSTRING_INDEX(
  SUBSTRING_INDEX(image_url, 'dream-archive/', -1),
  '?', 1
)
WHERE image_url LIKE 'http%';

UPDATE user
SET avatar_url = SUBSTRING_INDEX(
  SUBSTRING_INDEX(avatar_url, 'dream-archive/', -1),
  '?', 1
)
WHERE avatar_url LIKE 'http%';
```

**用 SUBSTRING_INDEX 而不是 REGEXP_REPLACE 的原因**：兼容所有 MySQL 版本（5.7 也支持），不依赖正则函数。

## 五、后续修复记录

### 5.1 游客禁止上传图片

**原因**：游客只应记录文字，图片上传是登录用户的功能。

**改动**：`RecordDreamView.vue` 中图片上传区域（PC 侧边栏 + 手机步骤 1）加 `v-if="userStore.isLoggedIn"`，隐藏 file input，handleSubmit 中图片上传逻辑加登录判断。

### 5.2 梦境列表不显示图片

**原因**：`DreamListView.vue` line 146 的 map 漏了 `imageUrl` 字段，后端返回的数据被丢弃了。

**改动**：
- `DreamListView.vue` map 中补上 `imageUrl: d.imageUrl || ''`
- `dream.ts` 的 `DreamDetail` 接口补上 `imageUrl?: string`

### 5.3 删除梦境时清理 MinIO 对象

**原因**：原来删除梦境只删数据库记录和重建统计，MinIO 里的图片没删，长期会堆积孤儿图片。

**改动**：`DreamService.deleteDream()` 中，DB 删除成功后，提取 imageUrl 的 objectName 并调用 `minioService.deleteObject()`。

### 5.4 文件上传安全加固

**问题**：原来只检查 `contentType.startsWith("image/")`，客户端可以伪造。

**改动（三层防护）**：

| 层级 | 位置 | 说明 |
|------|------|------|
| Spring 全局 | `application.properties` | `max-file-size=5MB`, `max-request-size=10MB`，大文件在 Controller 前就被拦截 |
| 白名单 | `FileController` | 只允许 `image/jpeg`、`image/png`、`image/webp` |
| 魔数校验 | `FileController.isValidImageHeader()` | 读文件头前 12 字节：JPEG=`FF D8 FF`，PNG=`89 50 4E 47`，WebP=`RIFF....WEBP`，伪造 contentType 也过不了 |

**为什么不用第三方库**：Spring Boot 自带 multipart 支持，魔数校验只需读几个字节，不需要额外依赖。

### 5.5 AI 解梦支持图片+文字联合分析

**需求**：用户上传手绘图片后，AI 应该同时看图和读文字来分析梦境，而不是只分析文字。

**改动链路**：

```
DreamController → DreamAiTaskService → AiService → AI API
```

| 文件 | 改动 |
|------|------|
| `DTO/Message.java` | `content` 字段从 `String` 改为 `Object`，支持纯文字和多模态两种格式 |
| `AiService.java` | 新增 `analyzeDream(content, imageUrl)` 重载，有图片时用多模态格式发送 |
| `DreamAiTaskService.java` | `completeDreamAiFields` 加 `imageUrl` 参数 |
| `DreamController.java` | 保存并分析、重新解析两处调用都传递 imageUrl |

**多模态消息格式**（OpenAI vision API 标准）：

```json
{
  "role": "user",
  "content": [
    { "type": "text", "text": "用户描述的文字" },
    { "type": "image_url", "image_url": { "url": "预签名URL" } }
  ]
}
```

**两种模式**：

| 模式 | 系统提示词 | user message |
|------|-----------|-------------|
| 有图片 | "综合图片画面元素（场景、人物、色彩、构图）和文字描述分析梦境" | 多模态（文字 + 图片） |
| 无图片 | "根据文字描述分析梦境" | 纯文字 |

**图片处理流程**：
1. 数据库存的是 objectName（如 `dreams/xxx.png`）
2. 调用 AI 前，`minioService.extractObjectName()` 提取 objectName
3. `minioService.getPresignedUrl()` 生成临时 URL
4. 拼成 `image_url` 格式发给 AI

**注意事项**：
- 有图片时超时从 30s 放宽到 60s（视觉模型处理更慢）
- 如果 AI 模型不支持 vision（如当前 mimo-v2.5-pro），图片部分会被忽略，降级为纯文字分析
- 后续接入支持 vision 的模型后，图片分析自动生效，无需改代码

### 5.6 多模态分析降级修复

**问题**：mimo-v2.5-pro 不支持 vision，发多模态格式直接返回 404，用户看到"AI 解析失败"。

**修复**：`AiService.analyzeDream()` 加降级逻辑：

```java
if (hasImage) {
    try {
        return analyzeDreamWithImage(content, imageUrl);
    } catch (Exception e) {
        log.warn("图片分析失败，降级为纯文字分析: {}", e.getMessage());
    }
}
// 无图片 or 图片分析失败 → 纯文字分析
```

**效果**：
- 有图片 + 支持 vision 的模型 → 图片+文字联合分析
- 有图片 + 不支持 vision 的模型 → 自动降级为纯文字，打 warn 日志，用户无感知
- 无图片 → 纯文字分析

**重构**：把原来的 `analyzeDream(content, imageUrl)` 拆成两个方法：
- `analyzeDream(content, imageUrl)` — 入口，含降级逻辑
- `analyzeDreamWithImage(content, imageUrl)` — 纯多模态调用，失败直接抛异常
