个人概述

以 RAG 与 Agent 工程落地 为主线，把「检索准不准、回答稳不稳、成本可不可控」 当作三个必须同时解决的问题。做法上倾向先打通链路再谈调优： 文档切分与向量化 → 召回与重排 → 提示词与上下文拼装 → 结构化输出与兜底。

有完整服务端开发经验，因此不只停留在调用接口，能自己把 向量库、后端服务与前端交互 串起来部署上线，也清楚每个环节会在哪里出问题。

方法论

  • 先评估再调优：没有召回率与回答质量的基线，就谈不上优化提示词。
  • 可控优先：能用规则约束的地方不用模型猜，尤其是涉及数据写入的操作。
  • 成本意识：缓存、上下文裁剪、分级模型使用，都是工程手段而非玄学。
  • 可观测：记录每次调用的输入摘要、召回片段与耗时，出问题能复现。
